• 結論として、現状は「手法検証用の研究プロトタイプ」としては面白いですが、BLSコールの自動判
  定・採点にそのまま使える精度にはまだ達していません。特に現在の強制Beam Searchは、評価用途
  では偽陽性を生みやすい構造です。

  ### 現状で良い点

  - Whisper large-v3-turboを使い、日本語を明示している
  - condition_on_previous_text=Falseで反復ループを抑えている
  - pyannoteで話者分離し、生音声と加工音声を比較している
  - Beam Search途中候補や確率をログとして残している
  - BLS用語を通常のWhisperがどの順位に出すか調査できる

  large-v3-turboは高速で、精度低下を比較的小さくした公式モデルです。ただしOpenAIも、特定領
  域での十分な評価と、発話されていない文章を生成するハルシネーションへの注意を求めていま
  す。Whisper公式モデルカード

  ### 重要な問題

  1. 目的語を強制生成している

  現行設定は、候補上位5件に「傷」「周囲」「体」「胸」の先頭トークンがあれば、hardモードで他
  候補をほぼ除外します。src/beam_hook.py:563

  これは「傷病者というコールが実際にあったか」を調べる際に、「傷病者を出すようデコーダーを
  操作してから、傷病者が出たか確認する」循環になっています。既存ログにも「傷病者」の不自然
  な反復が見られます。

  したがって、この結果をそのままコール実施の証拠にはできません。強制Beam Searchは研究対象と
  して残してよいですが、採点系とは分離すべきです。

  2. use_bias=Falseでも強制処理が有効になり得る

  src/run_whisper_bls.py:56では、inspect_cfgが有効ならフックが入ります。
  InspectConfig.enable_forceの既定値がTrueなので、通常認識のつもりでも強制処理が動く可能性
  があります。

  3. 正解データと評価指標が不足している

  確認できた教師データはtrain=9件、dev=1件で、独立したテストセットや次の指標がありません。

  - 文字起こし：CER
  - 話者分離：DER
  - コール検出：Precision、Recall、F1
  - 採点：専門家スコアとのMAE、相関、評価者間一致度
  - 特に重要：発話されていないコールを「あり」とする偽陽性率

  参加者単位・撮影日単位でデータを分割しないと、同じ声や同じ環境が学習側とテスト側に入り、
  実際より高い精度が出る可能性があります。

  4. 文字列の完全一致だけでは弱い

  scripts/bls_transcribe.py:65は、ひらがな化した文字列の包含判定です。

  例えば以下を十分に区別できません。

  - 「119番お願いします」と「119番通報してください」
  - 指導者が模範として発言した場合
  - 「まだAEDを持ってこなくていい」のような否定
  - 協力者の復唱
  - Whisperの一文字だけの誤認識

  5. 音声だけでBLS全体を100点評価するのは難しい

  胸骨圧迫の深さ・テンポ・解除、電極パッド装着、接触回避など、音声だけでは判断できない項目
  があります。JRC 2025に沿った項目定義が必要です。JRC蘇生ガイドライン2025

  そのため、当面は「BLS総合点」ではなく「音声から確認できるコール実施点」と明記するのが安全
  です。

  ### より良い解析方法

  おすすめは、強制文字起こしではなく、次の二段階構成です。

  音声
    → VAD・話者分離
    → 改変しないWhisper文字起こし＋N-best候補
    → コール候補区間の抽出
    → 音声・文字列・意味・話者・時系列を使ったイベント判定
    → 信頼度付きスコア＋根拠時刻

  コール判定には以下を組み合わせます。

  - 完全一致
  - ひらがな化＋編集距離による類似判定
  - WhisperのN-best候補と音響確率
  - 短文の意味分類
  - 発言者の役割
  - 否定・復唱・指導者発言の除外
  - BLS手順の時系列整合性
  との比較価値があります。公式ベンチマークでは、多くのデータセットで旧3.1より改善していま
  す。pyannote.audio公式リポジトリ

  最優先で行うべきなのは、「強制なしWhisper」を基準系に固定し、専門家が付けた正解ラベルとの
  Precision・Recallを測ることです。現行の強制Beam Searchは比較対象として残し、Recallが上が
  る代わりに偽陽性がどれだけ増えるかを実験すると、研究としても筋の良い構成になります。
